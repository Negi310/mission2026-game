# 提供音源の組み込み

関連: [Issue #5](https://github.com/Negi310/mission2026-game/issues/5)

## 音の割り当て

| 元ファイル | Unityアセット | 再生する場面 |
| --- | --- | --- |
| 大砲2.mp3 | Resources/Audio/Cannon.mp3 | 通常砲撃の発射 |
| 爆発1.mp3 | Resources/Audio/ExplosionA.mp3 | 砲弾・ミサイルの着弾 |
| 爆発2.mp3 | Resources/Audio/ExplosionB.mp3 | 車・ドラム缶の誘爆、破片の接触爆発 |
| 大爆発2.mp3 | Resources/Audio/BigExplosion.mp3 | 燃料タンク、ギガント爆弾、戦車の爆発 |

Downloads内の原本は保持し、同じバイト列をAssets/TankTown/Resources/Audioにコピーしました。取得・アイテム発動の短い合成音は継続使用します。

## 再生の制御

- 初期化時に4音源を読み込み、モノラルPCMへ展開して最初の発射を待たせません。インポート設定はこのAudioフォルダーだけに適用します。
- AudioSourceは12個を再利用します。発射2音、大爆発2音、その他8音の専用枠を設け、連鎖による無制限の音源生成を防ぎます。
- 車などの連鎖音は35ms、破片の接触音は70ms以内の重複を間引きます。破片の音量は低く設定しています。
- 重なった音は種類ごとの合計音量と全体の合計音量を自動調整します。小さい爆発だけが発射・大爆発をかき消さないようにし、提供音源の音量の合計を0.9以下に保ちます。
- 発射音は一定の音量、爆発音は発生地点の方向・距離を反映します。ドップラー効果は使いません。±3%のピッチ変化には物理演出とは別の乱数を使います。
- 発射クールタイム中やアイテムへの入力では通常の発射音は鳴りません。ポーズで音の再生位置も止まり、再開時に続きから再生します。結果画面では全音を停止します。

## 検証

Unity 6000.3.19f1の分離した検証プロジェクトで確認しました。元のプロジェクトのPackages・設定・シーンを使って検証を起動せず、確認済みのWindows実行ファイルをBuilds/TankTownへ反映しています。

- PlayMode全84件: 84/84成功、113.98秒。読み込み・デコード、発射クールタイム、音源の割り当て、固定数の再生枠、ポーズ・結果での停止を含みます。
- 音量の自動調整を追加した後、音声4件を再実行: 4/4成功、3.04秒。
- Windows Development Build: 成功。
- 最終ビルドの音声診断: 発射2回、着弾101回、連鎖1回、大爆発1回、再生枠12個、ポーズ・再開・結果での停止を確認。AudioListenerの実出力ピークは0.535。音量調整前は大量着弾で1.850だったため、合計音量の制御を追加しました。これは自動診断の出力測定であり、手動の聴感評価ではありません。
- 組み込み直後の街のWindows診断: 走行車18台・信号17か所、実砲撃で車が2台誘爆、連鎖6回・最大4段、屋上報酬の落下と回収、2.001秒のビーム、結果画面まで成功。
- 4つのMP3はDownloadsの原本とSHA-256が一致しています。取り込み後の長さは大砲2が2.795秒、爆発1が3.422秒、爆発2が2.612秒、大爆発2が5.064秒。全てモノラル・読み込み済み・非無音のPCMとしてプレイヤーでデコードできています。

記録: Logs/sound-effects-tests.xml、Logs/sound-effects-mix-tests.xml、Logs/sound-effects-build.log、Logs/sound-effects-audio-player.log、Logs/sound-effects-city-player.log。

`--tank-town-audio-smoke` は4アセットのデコードと音量ピーク、実砲撃入力、着弾・連鎖・大爆発の再生、AudioListenerの出力、ポーズ中の再生位置、再開、12音の上限、結果画面での停止を確認します。爆発の位置・半径は診断用に固定します。
