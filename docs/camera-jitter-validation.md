# 旋回時のカメラのガクつき

これは回転補間を修正した段階の記録です。その後、戦車と周囲を見渡せるよう後方9.0・高さ3.0へ引きました。[現在のカメラ距離の検証](camera-framing-validation.md) を参照してください。

実施日: 2026-10-02。砲塔と車体表示の回転を同じ描画時刻で補間し、物理更新ごとの段差をカメラが拾う問題を修正しました。カメラは描画された砲塔と常に同じ向き。後方3.0・高さ2.4・視野角72度を維持します。

## 修正

砲塔の先行角と車体の傾きは従来通りFixedUpdateで計算し、前回と今回の値を保持します。LateUpdateでは物理ステップ間の時刻に合わせて砲塔・車体表示の回転を補間。車体の表示姿勢は世界座標で指定し、親の物理回転の段差が再び表示へ混ざらないようにします。Rigidbodyの移動・当たり判定・地面追従は維持します。

表示更新 → カメラ更新（順序50）→ 照準更新（順序100）の順に実行します。カメラだけを遅らせず、カメラと砲塔の方向・傾斜を毎フレーム一致させます。Warp時には前回と今回の姿勢を安全位置へ揃え、復帰時に古い向きから補間しません。速度16・加速度10、車体遅延0.08秒・操舵応答12・砲塔先行角22度は変更しません。

UnityのRigidbody補間は物理更新間をつなぐための仕組みです。[Unity公式のRigidbody補間の説明](https://docs.unity3d.com/6000.3/Documentation/Manual/rigidbody-interpolation.html)

## 検証

回帰テストでは、120fps相当の描画時計と0.08秒の物理更新を組み合わせ、更新頻度の差を強調します。旋回と切り返し中のカメラ回転を描画前に毎フレーム計測。方向一致だけでなく、1フレームに物理ステップ分をまとめて回転することがないかも確認します。

修正前はカメラの最大回転速度が2016.05度/秒になり、400度/秒未満を要求するテストが失敗して問題を再現しました。通常の車体85度/秒と砲塔210度/秒に対して、段階的な回転で大きな跳ね上がりが出ています。再現XMLは `Logs/camera-jitter-before-tests.xml`。

最終の関連PlayMode **12件成功・0件失敗**（27.67秒）。カメラ距離と方向一致、旋回・切り返し、砲塔先行と実際の砲撃方向、加速と操舵の慣性、実際の坂と頂上、砲身の上向き4度、衝突復帰、一時停止と結果・再開始、ビーム、巨大化、高速・街の外からの復帰を確認しました。最終XMLは `Logs/camera-jitter-final-tests.xml`。

更新周期を変えた回帰テストでは、102描画フレームの最大回転速度が**209.93度/秒**、最大フレーム回転量1.749度、カメラと砲塔の方向ベクトル差0.000000でした。回転の跳ね上がりを抑えつつ、方向一致を維持しています。ログは `Logs/camera-jitter-final-tests.log`。

Windows x64 Development Build成功。Direct3D 11 / GTX 1660 Tiの実プレイヤーで、60・144fpsを目標に旋回と切り返しの連続フレームを測定しました。画像保存は測定後の別の走行で実行し、PNGの読み取り・保存による停止を測定へ混ぜていません。
