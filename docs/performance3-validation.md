# 描画と破壊時の再構築の軽量化（2026-10-24）

## 変更

- 通行人の16〜17個のMeshRendererを、3材質・5ボーンのSkinnedMeshRendererに統合。帽子と髪の2種類のメッシュを街全体で共有します。形・色・影・歩行の4関節・吹き飛び・命中判定は保持しています。
- 車は全台で同じ結合済みメッシュを共有し、車体の材質だけを切り替えます。非表示の元モデル部品を各車に残さず、ルートの衝突形状・走行・誘爆は従来の処理を使います。
- 建物の描画用に、固定部材の形状・材質・建物に対する変換行列を生成時に記録。破壊やひび、カメラ透過の変更時には残っている部材だけを結合します。
- メッシュ結合の材質グループ・長さ別の入力配列・中間メッシュを街単位で再利用。結合後の描画メッシュは従来どおり不要なCPUコピーを解放します。街の破棄時に共有メッシュと作業領域を解放します。

建物の詳細表示距離160/185m、破片上限2,000個・寿命・衝突・連鎖判定、武器とエフェクトの設定値は変更していません。

## PlayMode

Unity 6000.3.19f1の既存の検証コピーを使用。`TankTownPerformanceTests`・`TankTownCityTests`・`TankTownCityKitTests`・`TankTownChainPolishTests`・`TankTownCandyTests`の32件が全て成功（125.60秒）。

新しい確認は、通行人の共有メッシュ2種類・3材質・関節の実際の変形（BakeMesh）、車の形状共有・色と当たり判定の維持、複数材質の結合・部材削除・中間メッシュの再利用です。既存の砲撃・車の誘爆・通行人への命中・お菓子の輪郭・部分破壊・カメラ透過・遠近切り替えも通過しています。

記録：`Logs/perf3-tests.xml`、`Logs/perf3-tests.log`。

## 計測条件

Windows x64 Development Build、Direct3D 11、1920×1080。CPUはCore i7-9700、GPUはGeForce GTX 1660 Ti 6GB。シード2026の大型街とお菓子の街で、同一の`--tank-town-performance-smoke`を実行します。

各描画をRenderTextureへ描き、1ピクセルのReadPixelsで完了を待ちます。街とHUDを実際に描く測定です。タイトル、固定位置からの街（診断用ミニマップ有効・無効）、巨大爆弾後の2.8秒の4区間を記録します。ミニマップは通常のHUDには表示されません。

最初の基準測定は回ごとの差が大きかったため、最終比較は旧・新の実行順を入れ替えた交互測定を使います。物理破片と通行車両があるため、同じシードでも倒壊量やフレーム時間は完全には一致しません。これは短時間の負荷試験であり、全場面の平均FPSを保証するものではありません。巨大爆弾の`Detonate()`が同期的に行う初期破壊は測定区間の直前で、区間の数値には含みません。

計測スクリプト：`Logs/Measure-Perf3Paired.ps1 -Prefix perf3-final-paired`。結果とログ：`Logs/perf3-final-paired-*-results.json`、`Logs/perf3-final-paired-*-player.log`。集計は`Logs/perf3-final-summary.json`です。

## 結果

旧→新の順と新→旧の順で各2回。以下は各試行の平均フレーム時間の算術平均です。小さいほど高速です。

| ステージ・場面 | 旧 ms | 新 ms | 処理時間の減少 | 描画命令 旧→新 |
| --- | ---: | ---: | ---: | ---: |
| 大型街・タイトル | 6.58 | 6.90 | −4.9% | 3,397→3,397 |
| 大型街・街／マップ更新あり | 13.72 | 11.41 | 16.8% | 11,892→8,652 |
| 大型街・街／マップ更新なし | 13.66 | 10.86 | 20.5% | 11,793→8,560 |
| 大型街・巨大爆弾後 | 45.42 | 40.12 | 11.7% | 14,954→11,779 |
| お菓子・タイトル | 7.08 | 6.94 | 1.9% | 3,396→3,396 |
| お菓子・街／マップ更新あり | 15.81 | 13.71 | 13.3% | 12,257→9,007 |
| お菓子・街／マップ更新なし | 16.19 | 13.45 | 17.0% | 12,096→8,859 |
| お菓子・巨大爆弾後 | 49.81 | 44.07 | 11.5% | 14,086→10,898 |

通常の街の描画命令は大型街27.4%減、お菓子26.8%減。タイトルは通行人や車がいないため同じ描画数で、処理時間の差は測定のばらつきの範囲です。

倒壊区間の`GC Allocated In Frame`は大型街179.7→78.6 KiB/フレーム（56.3%減）、お菓子209.4→66.5 KiB/フレーム（68.3%減）。これは一時的なマネージドメモリ確保量で、ゲーム全体の使用メモリではありません。全8回とも破片の最大数は2,000個でした。終了時の破壊部材数は大型街で旧1,992〜2,187・新2,267〜2,519、お菓子で旧2,148〜2,207・新2,350〜2,514です。

大量倒壊の負荷はまだ残ります。p95の各試行平均は大型街117.7→85.5ms、お菓子99.8→99.6msで、お菓子の重いフレームはほぼ改善していません。破片の生成・物理演算・連鎖の集中が次の調整対象です。この計測から大量倒壊中の60fps維持は主張できません。
